9.1 流式输出

长回答如果等全部生成完才显示，体验很差。用 stream 逐 token 输出：

from langchain_openai import ChatOpenAI
from langchain_core.prompts import ChatPromptTemplate

model = ChatOpenAI(model="gpt-4o-mini", temperature=0)
prompt = ChatPromptTemplate.from_template("写一篇关于{主题}的短文")

chain = prompt | model

for chunk in chain.stream({"主题": "人工智能"}):
    print(chunk.content, end="", flush=True)   # 逐字打印

Agent 的流式输出更复杂，会流式返回中间状态（thought、工具调用、最终答案）：

for chunk in agent.stream({"messages": [("user", "...")]}, stream_mode="values"):
    last = chunk["messages"][-1]
    if hasattr(last, "tool_calls") and last.tool_calls:
        print(f"\n[调用工具] {last.tool_calls[0]['name']}")
    elif last.content:
        print(f"\n[回答] {last.content}")

9.2 回调与可观测性

生产环境必须能观测 Agent 的运行：记录每次模型调用、工具调用、耗时、token 用量、报错。LangChain 通过回调系统实现：

from langchain_core.callbacks import BaseCallbackHandler

class MyHandler(BaseCallbackHandler):
    def on_llm_start(self, serialized, prompts, **kwargs):
        print(f"[LLM 开始] {len(prompts)} 个提示")

    def on_llm_end(self, response, **kwargs):
        usage = response.llm_output.get("token_usage", {})
        print(f"[LLM 结束] tokens={usage}")

    def on_tool_start(self, serialized, input_str, **kwargs):
        print(f"[工具开始] {serialized.get('name')}")

# 全局注入
agent = create_agent(model=model, tools=[...])
result = agent.invoke({...}, config={"callbacks": [MyHandler()]})
💡 生产级可观测性 推荐接入专业平台（如 LangSmith、Langfuse、Phoenix），它们能自动记录完整的调用链、token 成本、延迟、质量评估。手写回调适合快速调试，正式上线建议用成熟方案。

9.3 LangGraph 与状态化工作流

当 Agent 需要显式状态、条件分支、循环、人工介入、多智能体协作时，LCEL 的线性管道就不够用了。这时用 LangGraph，它把应用建模为「节点（node）+ 边（edge）」的图：

# 安装
pip install "langgraph>=1.0"

from langgraph.graph import StateGraph, START, END
from typing_extensions import TypedDict

class State(TypedDict):
    question: str
    answer: str

def answer_node(state: State) -> dict:
    return {"answer": model.invoke(state["question"]).content}

builder = StateGraph(State)
builder.add_node("answer", answer_node)
builder.add_edge(START, "answer")
builder.add_edge("answer", END)

graph = builder.compile()
print(graph.invoke({"question": "什么是 LangGraph？"}))

LangGraph 的核心价值：

  • 循环：Agent 的 ReAct 循环本质是「有环的图」，LangGraph 原生支持。
  • 人工介入（Human-in-the-loop）：用 interrupt 在关键节点暂停，等待人工批准。
  • 状态持久化：用 checkpointer 保存图状态，支持恢复与时间旅行调试。
  • 多智能体：多个 Agent 作为子图，相互协作。

条件分支示例

下面用 add_conditional_edges 实现「按问题类型走不同分支」，这是 LangGraph 区别于线性链的核心能力：

from langgraph.graph import StateGraph, START, END
from typing_extensions import TypedDict, Literal

class State(TypedDict):
    question: str
    answer: str

def route(state: State) -> Literal["order", "policy"]:
    """根据关键词决定走哪个分支"""
    if "订单" in state["question"] or "物流" in state["question"]:
        return "order"
    return "policy"

def order_node(state: State) -> dict:
    return {"answer": f"[订单分支] 处理订单问题：{state['question']}"}

def policy_node(state: State) -> dict:
    return {"answer": f"[政策分支] 处理政策问题：{state['question']}"}

builder = StateGraph(State)
builder.add_node("order", order_node)
builder.add_node("policy", policy_node)
builder.add_conditional_edges(START, route)  # 按 route 结果分流
builder.add_edge("order", END)
builder.add_edge("policy", END)

graph = builder.compile()
print(graph.invoke({"question": "我的订单怎么还没到？"}))
{'answer': '[订单分支] 处理订单问题：我的订单怎么还没到？'}

9.5 部署方案

把 Agent 变成可对外服务的 API，常见两种路径：

方案适用场景技术栈
FastAPI 服务自建后端，灵活控制FastAPI + LangChain + uvicorn
LangServe快速把链/Agent 发布为 REST APILangServe（LangChain 官方）
LangGraph Platform生产级部署、持久化、监控LangGraph Cloud / 自托管
 
# FastAPI 最小示例
from fastapi import FastAPI
from pydantic import BaseModel

app = FastAPI()

class AskRequest(BaseModel):
    question: str

@app.post("/ask")
def ask(req: AskRequest):
    # 复用第 08 章的 agent
    result = agent.invoke({"messages": [("user", req.question)]})
    return {"answer": result["messages"][-1].content}

# 运行：uvicorn main:app --reload
✅ 最佳实践：部署注意事项 上线前务必处理：并发控制（Agent 多轮调用耗时长，用异步 + 队列）、超时（设置请求上限）、限流（防成本攻击）、密钥管理（用云密钥服务）、日志与监控（可观测性）。

方面优化手段

9.7 安全清单

❌ 安全红线清单
  • 提示注入：外部内容（网页、文档、用户输入）可能诱导模型越权。明确「外部内容不可信」。
  • 数据泄露：不要把密钥、客户隐私塞进提示词；日志脱敏。
  • 工具越权：写操作需人审 + 权限校验 + 审计日志。
  • 输出校验：模型输出用于下游（如 SQL、代码执行）前必须校验/沙箱。
  • 成本攻击：限制单用户调用频率、最大 token、最大迭代次数。
