02 链（Chain）

阶段一 · 入门 难度：入门 前置：01 环境搭建

学习目标

  • 理解 Runnable 接口与 LCEL
  • 用管道符 | 编排多步流程
  • 掌握 invoke / stream / batch 三种调用方式

前置知识

  • 01 章节的模型调用
  • 函数式编程直觉（管道、组合）

2.1 什么是「链」

在真实应用中，很少只调用一次模型。通常需要：格式化提示 → 调用模型 → 解析输出 → 后处理。「链（Chain）」就是把多个步骤组合成一条流水线。

LangChain 1.x 中，一切可调用组件都实现统一的 Runnable 接口。通过 LCEL（LangChain Expression Language），你可以用管道符 | 把多个 Runnable 串联起来，像搭积木一样。

💡 LCEL 是什么 LCEL 是一套声明式语法，用于组合 Runnable。它自动提供：流式传输、批处理、异步调用、重试与回退、并行执行、运行时配置等能力。这是 LangChain 最核心、最值得掌握的设计。

2.2 Runnable 接口

每个 Runnable 都有统一的调用方法：

方法说明适用场景
invoke(input)同步调用，返回完整结果普通脚本
stream(input)流式返回，逐 token 输出聊天界面、长文本
batch(inputs)批量处理，返回结果列表批量任务
ainvoke / astream异步版本Web 服务、高并发

2.3 LCEL 基础：管道编排

下面用 prompt | model 组合出第一条链。提示模板（第 03 章详解）先格式化输入，再交给模型：

from langchain_openai import ChatOpenAI
from langchain_core.prompts import ChatPromptTemplate

model = ChatOpenAI(model="gpt-4o-mini", temperature=0)

prompt = ChatPromptTemplate.from_template(
    "把下面的内容翻译成{language}：\n{text}"
)

# 用 | 串联成链
chain = prompt | model

result = chain.invoke({
    "language": "英文",
    "text": "今天天气很好，适合出去散步。",
})
print(result.content)
The weather is nice today, perfect for going out for a walk.

链中的数据流

LCEL 的 | 会把左侧的输出作为右侧的输入。因此每一步的输出类型必须与下一步的输入类型匹配。上面的例子：prompt 输出 PromptValue，恰好是 model 的输入。

2.4 多步链与输出解析

引入 StrOutputParser 把 AIMessage 转成纯字符串，并串联多个步骤：

from langchain_core.output_parsers import StrOutputParser

outline_prompt = ChatPromptTemplate.from_template(
    "为「{topic}」生成一份 3 点大纲，每点不超过 15 字。"
)
expand_prompt = ChatPromptTemplate.from_template(
    "请把下面的提纲展开成一段连贯的文字：\n{outline}"
)

chain = (
    outline_prompt
    | model
    | StrOutputParser()      # AIMessage -> str
    | (lambda outline: {"outline": outline})  # 适配下一步输入
    | expand_prompt
    | model
    | StrOutputParser()
)

print(chain.invoke({"topic": "量子计算"}))
⚠️ 常见误区：输入字典键不匹配 新手最常见的报错是 KeyError：链中某一步期望的输入键，与上一步实际输出的键不一致。上面的 lambda outline: {"outline": outline} 正是为了解决「上一步是字符串、下一步需要字典」的键对齐问题。

2.5 RunnableLambda 与自定义函数

普通 Python 函数可以包装成 RunnableLambda，从而加入链中：

from langchain_core.runnables import RunnableLambda

def count_words(text: str) -> str:
    return f"该段文字共 {len(text)} 个字符。"

chain = (
    prompt | model | StrOutputParser()
    | RunnableLambda(count_words)
)
print(chain.invoke({"language": "英文", "text": "你好，世界"}))

2.6 并行执行：RunnableParallel

当多个分支可以同时计算时，用 RunnableParallel（字典形式）并行执行，最后汇总：

from langchain_core.runnables import RunnableParallel

# 同一输入，同时生成「优点」和「缺点」
pros_prompt = ChatPromptTemplate.from_template("列出「{topic}」的 3 个优点")
cons_prompt = ChatPromptTemplate.from_template("列出「{topic}」的 3 个缺点")

chain = RunnableParallel(
    pros=pros_prompt | model | StrOutputParser(),
    cons=cons_prompt | model | StrOutputParser(),
)

result = chain.invoke({"topic": "远程办公"})
print("优点：\n", result["pros"])
print("缺点：\n", result["cons"])
✅ 最佳实践：可维护性 复杂的链会迅速变得难以阅读。建议：给每个子链命名（用变量名如 translate_chain），拆分为小函数，并在关键节点加注释说明数据流。超过 3 步的链，考虑用第 09 章的 LangGraph 做显式状态管理。

2.8 异步与批处理

生产环境中，同步调用会阻塞事件循环。用异步版方法（ainvoke/astream/abatch）可以并发处理多个请求：

import asyncio

async def main():
    # 并发调用 3 个不同翻译
    tasks = [
        chain.ainvoke({"language": "英文", "text": "你好"}),
        chain.ainvoke({"language": "日语", "text": "谢谢"}),
        chain.ainvoke({"language": "法语", "text": "再见"}),
    ]
    results = await asyncio.gather(*tasks)  # 并发执行
    for r in results:
        print(r)

asyncio.run(main())

2.9 错误处理与回退

链可以配置重试和回退（fallback），提升健壮性：

from langchain_openai import ChatOpenAI

# 主模型 + 备用模型
primary = ChatOpenAI(model="gpt-4o", timeout=5)
fallback = ChatOpenAI(model="gpt-4o-mini", timeout=10)

# 主模型失败时自动回退到备用模型
robust_chain = (primary.with_fallbacks([fallback])) | StrOutputParser()

# 带重试：失败自动重试 3 次
from langchain_core.runnables import RunnableRetry
retried = RunnableRetry(bound=chain, max_attempt_number=3)
✅ 最佳实践：健壮性 网络抖动、限流、超时在真实环境很常见。为链配置 with_fallbacks（备用模型）与重试，是生产系统的必备项，能显著降低故障率。

2.10 动手练习

练习 2.1：构建翻译链 （入门）

用 LCEL 构建一条链：输入一段中文和「目标语言」，输出对应语言的翻译，并将结果转为纯字符串。

验证方法：传入「目标语言=法语」，观察输出为法语文本，且 type() 为 str。
练习 2.2：并行生成方案对比 （入门）

用 RunnableParallel 同时生成「方案 A」和「方案 B」两套营销文案，分别用不同的 temperature，比较差异。

验证方法：一次 invoke 返回包含两个键的字典，且两个方案内容明显不同。
练习 2.3：调试数据流 （进阶）

给 2.4 的多步链在中间插入一个 RunnableLambda，打印每一步的中间输出，观察数据如何流转。

验证方法：控制台能看到「提纲」与「正文」两个阶段的中间结果，理解输入输出类型变化。
练习 2.4：异步并发调用 （进阶）

用 ainvoke + asyncio.gather 并发翻译 3 段文本，对比与顺序调用的耗时差异。

验证方法：并发调用总耗时显著小于顺序调用之和（约等于最慢的那一个），理解异步的价值。
练习 2.5：配置回退 （高级）

为主模型配置一个 with_fallbacks 备用模型，故意让主模型超时（如设置极小的 timeout），观察是否自动回退。

验证方法：主模型超时后，链自动用备用模型返回结果，全程不抛异常。
