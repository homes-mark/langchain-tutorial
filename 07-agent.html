  • 掌握 ReAct 循环与多工具协作

前置知识

  • 工具定义与绑定（06）

7.1 链 vs 智能体

链是固定的流水线：步骤和顺序在写代码时就定死了。智能体则让模型自主决策：根据当前情况，动态决定「调用哪个工具、调用几次、什么时候停、什么时候给出最终答案」。

特性链（Chain）智能体（Agent）
控制流固定、可预测动态、由模型决定
适用场景流程明确的批量任务开放、需自主决策的任务
成本/延迟低、可预估高、不确定（多轮）
可调试性好较难

原则：能用链解决的，不要用 Agent。Agent 灵活性高，但成本、延迟、不可预测性也高。

7.2 ReAct 循环

主流 Agent 采用 ReAct（Reasoning + Acting） 模式，核心是一个循环：

  1. Thought（思考）：模型分析当前情况，决定下一步。
  2. Action（行动）：调用某个工具，或输出最终答案。
  3. Observation（观察）：拿到工具返回结果，回到第 1 步。

这个循环持续到模型决定「给出最终答案」为止。

7.3 用 create_agent 构建

LangChain 1.x 推荐用 langchain.agents.create_agent，它内部封装了 ReAct 循环与工具执行，返回一个可运行的 Agent：

from langchain_openai import ChatOpenAI
from langchain.agents import create_agent
from langchain_core.tools import tool

model = ChatOpenAI(model="gpt-4o-mini", temperature=0)

@tool
def get_weather(city: str) -> str:
    """查询城市天气。city 为中文城市名。"""
    db = {"北京": "晴，25°C", "上海": "多云，28°C", "深圳": "阵雨，30°C"}
    return db.get(city, f"暂无{city}数据")

@tool
def multiply(a: float, b: float) -> str:
    """计算两数乘积。"""
    return f"{a} × {b} = {a * b}"

agent = create_agent(
    model=model,
    tools=[get_weather, multiply],
    system_prompt="你是乐于助人的助手，能查天气、做计算。",
)

result = agent.invoke({
    "messages": [("user", "北京和上海的温差是多少？先查两地天气，再计算。")],
})
print(result["messages"][-1].content)
北京今天晴 25°C，上海多云 28°C，
上海比北京高 3°C（温差为 3 度）。
💡 关键点 这个例子展示了 Agent 的核心价值：模型自主判断需要先查两个城市天气（两次工具调用），再做计算。而普通链无法处理这种「根据问题动态决定调用几次」的场景。

调试 Agent 时，可以查看完整的消息历史，理解模型的决策过程：

for msg in result["messages"]:
    role = type(msg).__name__
    if hasattr(msg, "tool_calls") and msg.tool_calls:
        for tc in msg.tool_calls:

7.5 误区与最佳实践

❌ 误区：无限循环与失控 Agent 可能在多个工具间反复横跳、无法收敛。务必设置最大迭代次数（max_iterations），并对死循环、超时做兜底处理。
❌ 误区：成本失控 每次工具调用都要重新把整个历史发给模型，多轮循环 token 消耗巨大。应：精简 system 提示、控制历史长度、用便宜模型做简单步骤。
✅ 最佳实践
  • 给 Agent 一个清晰的 system_prompt，明确边界与行为规范。
  • 工具要职责单一、描述精准（见 06 章）。
  • 对危险操作加人工确认与权限控制。
  • 记录完整的执行轨迹，便于审计与调试。

7.6 带记忆的 Agent（完整实现）

Agent 默认无状态。要让它记住多轮对话，用 RunnableWithMessageHistory 包裹。注意 Agent 的输入/历史键都是 messages：

from langchain_core.chat_history import InMemoryChatMessageHistory
from langchain_core.runnables.history import RunnableWithMessageHistory

store = {}

def get_history(session_id: str):
    if session_id not in store:
        store[session_id] = InMemoryChatMessageHistory()
    return store[session_id]

agent_with_memory = RunnableWithMessageHistory(
    agent,
    get_history,
    input_messages_key="messages",   # Agent 输入键
    history_messages_key="messages", # 历史注入键（相同）
)

def ask(session_id: str, text: str) -> str:
    r = agent_with_memory.invoke(
        {"messages": [("user", text)]},
        config={"configurable": {"session_id": session_id}},
    )
    return r["messages"][-1].content

print(ask("u1", "我住在深圳"))
print(ask("u1", "帮我查一下我所在城市的天气"))  # 需要记住"我=深圳"
好的，已记住您住在深圳。
深圳今天阵雨，气温 30°C。
⚠️ 关键区别：键名是 messages 普通链用 input_messages_key="input"，而 Agent 的输入键是 messages（一个消息列表）。两处键名都要写 "messages"，否则会报 KeyError。这是最常见的坑。

7.7 不同 Agent 范式

除了最基础的 ReAct，LangGraph 生态还支持更高级的 Agent 架构：

范式特点适用场景
ReAct思考-行动-观察循环通用、最简单
Plan-and-Execute先规划再逐步执行复杂多步任务
多智能体（Supervisor）主管 Agent 调度多个子 Agent分工明确的复杂系统
结构化输出 Agent强制按 schema 输出需精确格式的场景

7.8 动手练习

练习 7.1：构建双工具 Agent （进阶）

用 create_agent 构建一个拥有「查天气」和「计算器」两个工具的 Agent，处理需要多工具协作的问题。

验证方法：问「上海和深圳哪个更热？温差多少度？」，Agent 能自动调用 get_weather 两次 + 计算，给出正确结论。
练习 7.2：追踪决策过程 （进阶）

打印 Agent 的完整消息历史，还原它每一步的思考与工具调用。

验证方法：能看到「调用工具 → 观察结果 → 继续/结束」的完整链路，理解 ReAct 循环。
练习 7.3：Agent + 记忆 （高级）

把第 04 章的 RunnableWithMessageHistory 与 Agent 结合，让 Agent 在多轮对话中记住上下文。

验证方法：第一轮说「我住在深圳」，第二轮问「查一下我所在城市的天气」，Agent 能结合记忆正确调用工具。
练习 7.4：限制 Agent 行为 （高级）

通过精心设计 system_prompt 约束 Agent：拒绝回答与工具无关的问题、限定工具使用次数，观察行为变化。

验证方法：问「帮我写一首诗」（与工具无关），Agent 能礼貌拒绝或引导回正题，而非乱调工具。
