05 检索增强生成（RAG）

阶段二 · 进阶 难度：进阶 前置：01–04

学习目标

  • 理解 RAG 的动机与整体流程
  • 掌握文档加载、切分、向量化、检索
  • 构建端到端的问答链

前置知识

  • LCEL 链式编排
  • 向量/嵌入的基本直觉

5.1 为什么需要 RAG

大模型的三大局限：

  • 知识截止：训练数据有时间上限，不知道新信息。
  • 私有知识缺失：不知道你公司的内部文档。
  • 幻觉（Hallucination）：会一本正经地编造不存在的事实。

RAG（Retrieval-Augmented Generation，检索增强生成）的思路：先从你的知识库检索出相关内容，再把内容「塞进」提示词，让模型基于这些材料回答，而不是凭空生成。

5.2 RAG 全流程

RAG 分两个阶段：索引（离线）和查询（在线）。先安装依赖：

pip install "langchain-text-splitters>=1.0" "langchain-community>=1.0"
pip install "langchain-chroma>=1.0" "chromadb"   # 向量库
# 嵌入模型（以 OpenAI 为例，或改用本地模型省成本）
pip install "langchain-openai>=1.0"

步骤 1：加载文档

from langchain_community.document_loaders import TextLoader

loader = TextLoader("./data/公司制度.txt", encoding="utf-8")
docs = loader.load()
print(len(docs), "个文档加载完成")

步骤 2：切分（Chunking）

文档太长，需要切成小片段，既能塞进上下文，也便于精确检索：

from langchain_text_splitters import RecursiveCharacterTextSplitter

splitter = RecursiveCharacterTextSplitter(
    chunk_size=500,        # 每块约 500 字符
    chunk_overlap=50,      # 块间重叠 50 字符，避免语义被切断
)
chunks = splitter.split_documents(docs)
print(f"切分为 {len(chunks)} 个片段")
⚠️ 常见误区：切分参数 chunk_size 太小会导致语义碎片化、检索不到完整上下文；太大则超出模型处理能力、且无关内容噪声多。通常 300–1000 字符较合适，chunk_overlap 设为 chunk_size 的 10%–20%。关键要按语义边界（如段落、标题）切分。

步骤 3：向量化并入库

from langchain_openai import OpenAIEmbeddings
from langchain_chroma import Chroma

embeddings = OpenAIEmbeddings(model="text-embedding-3-small")

vectorstore = Chroma.from_documents(
    documents=chunks,
    embedding=embeddings,
    persist_directory="./chroma_db",   # 持久化，下次直接加载
)

步骤 4：构建检索器

retriever = vectorstore.as_retriever(
    search_type="similarity",   # 相似度检索
    search_kwargs={"k": 4},     # 返回最相似的 4 块
)
relevant = retriever.invoke("年假可以休几天？")
print(relevant[0].page_content)

步骤 5：组成问答链

from langchain_core.prompts import ChatPromptTemplate
from langchain_core.output_parsers import StrOutputParser
from langchain_core.runnables import RunnablePassthrough
from langchain_openai import ChatOpenAI

model = ChatOpenAI(model="gpt-4o-mini", temperature=0)

prompt = ChatPromptTemplate.from_template(
    """请仅根据下面提供的资料回答问题。如果资料中没有答案，请明确说"资料中未提及"。

资料：
{context}

问题：{question}
回答："""
)

def format_docs(docs):
    return "\n\n".join(d.page_content for d in docs)

rag_chain = (
    {"context": retriever | format_docs, "question": RunnablePassthrough()}
    | prompt
    | model
    | StrOutputParser()
)

print(rag_chain.invoke("年假可以休几天？"))
根据公司制度，员工入职满 1 年可享受 5 天年假，
满 3 年可享受 10 天年假。
💡 这行代码在做什么 {"context": retriever | format_docs, "question": RunnablePassthrough()} 同时构造了字典的两个键：context 走「检索→拼接」，question 原样透传（RunnablePassthrough）。这是 RAG 链最经典的写法，务必理解。

5.3 提升检索质量

技术解决的问题说明
MMR结果重复最大边际相关，兼顾相关性与多样性
混合检索关键词匹配不足向量检索 + 关键词（BM25）结合
重排序（Rerank）Top-K 不够准用更精的模型对候选二次排序
元数据过滤范围限定按时间/分类/权限过滤
 
# MMR 检索示例
retriever = vectorstore.as_retriever(
    search_type="mmr",
    search_kwargs={"k": 4, "fetch_k": 20, "lambda_mult": 0.5},
)
✅ 最佳实践：性能与成本
  • 嵌入缓存：向量化是 RAG 最耗时的环节之一，对已处理文档做缓存，避免重复计算。
  • 异步 + 批量：大量文档用 abatch 或分批嵌入。
  • 本地嵌入模型：生产环境用 sentence-transformers 等本地模型，避免按 token 付费。
  • 评估：用真实问题集评估「命中率」与「答案准确率」，而非凭感觉调参。
❌ 误区：幻觉仍未根除 RAG 能显著降低幻觉，但不能完全消除。若检索结果质量差，模型仍可能编造。务必在提示中强制「资料未提及则明说」，并在关键场景加人工审核。

5.5 加载多种文档类型

真实项目要处理 PDF、Word、网页等各类文档。LangChain 提供大量 loader：

from langchain_community.document_loaders import (
    PyPDFLoader,          # PDF
    Docx2txtLoader,       # Word
    CSVLoader,            # CSV
    WebBaseLoader,        # 网页
    TextLoader,           # 纯文本
)

# 统一加载多个来源
loaders = [
    TextLoader("./data/制度.txt", encoding="utf-8"),
    CSVLoader("./data/产品目录.csv"),
    WebBaseLoader("https://example.com/faq"),
]
docs = []
for loader in loaders:
    docs.extend(loader.load())

print(f"共加载 {len(docs)} 个文档")
⚠️ 常见误区：忽略清洗 直接从 PDF/网页提取的文本常含乱码、页眉页脚、导航栏、多余空白。这些噪声会污染向量库、降低检索质量。入库前务必做文本清洗（去噪、去重、统一格式）。

5.6 对话式 RAG（带记忆的问答）

把 RAG 与第 04 章的记忆结合，让问答能理解「它」「上一个问题」等指代：

from langchain_core.prompts import ChatPromptTemplate, MessagesPlaceholder
from langchain_core.runnables.history import RunnableWithMessageHistory
from langchain_core.chat_history import InMemoryChatMessageHistory

# 带历史的 RAG 提示
prompt = ChatPromptTemplate.from_messages([
    ("system", "根据资料回答问题，资料不足则说明。\n\n资料：{context}"),
    MessagesPlaceholder("history"),
    ("human", "{question}"),
])

def format_docs(docs):
    return "\n\n".join(d.page_content for d in docs)

rag_chain = (
    {"context": retriever | format_docs, "question": RunnablePassthrough()}
    | prompt | model | StrOutputParser()
)

# 包一层记忆
store = {}
def get_history(sid):
    if sid not in store:
        store[sid] = InMemoryChatMessageHistory()
    return store[sid]

with_history = RunnableWithMessageHistory(
    rag_chain, get_history,
    input_messages_key="question",
    history_messages_key="history",
)

# 多轮问答
print(with_history.invoke("年假有几天？", config={"configurable": {"session_id": "s1"}}))
print(with_history.invoke("那病假呢？", config={"configurable": {"session_id": "s1"}}))  # "那"指代上文

5.7 RAG 评估：别凭感觉

RAG 有两类指标必须量化评估：

指标含义衡量
检索命中率检索结果里是否包含正确答案所在的片段检索器质量
答案准确率最终答案是否忠实于资料、是否正确端到端质量
忠实度（Faithfulness）答案是否完全基于检索内容（无幻觉）幻觉程度
 
# 评估思路：准备标注好的「问题-标准答案」对，批量跑分
test_set = [
    {"q": "年假有几天？", "expected": "入职满1年5天"},
    {"q": "试用期多久？", "expected": "3个月"},
    # ...
]
# 对每个问题：1) 检索，判断命中；2) 生成，比对答案
# 可结合 LangSmith / RAGAS 等工具自动化评估
✅ 最佳实践：迭代优化 RAG 优化 RAG 的正确姿势是「评估驱动」：先建立测试集与基线分数 → 改一个参数（如切分大小、检索策略）→ 重新评估对比 → 有提升才保留。切忌盲目堆技巧。

5.8 动手练习

练习 5.1：端到端 RAG （进阶）

准备一份 2–3 页的任意文本（如产品说明、公司制度），完整跑通「加载→切分→向量化→检索→问答」流程。

验证方法：问一个文档中明确存在的细节问题，模型能准确引用原文回答；问一个文档外的问题，模型回答「资料中未提及」。
练习 5.2：对比切分参数 （进阶）

分别用 chunk_size=200 和 chunk_size=800 构建两个向量库，对同一问题检索，对比返回片段的质量。

验证方法：观察 chunk_size 过小时返回片段语义不完整，过大时噪声多，找到适合你数据的参数。
练习 5.3：MMR 检索 （高级）

把检索器改为 mmr 类型，调整 lambda_mult，观察返回结果在「相关性」与「多样性」间的变化。

验证方法：lambda_mult 越大越看重相关性（结果可能重复），越小越看重多样性（结果更分散）。
练习 5.4：对话式 RAG （高级）

给 RAG 链接入记忆，实现多轮问答，让模型能理解「它」「上一个」等指代。

验证方法：连续问「年假有几天？」「那病假呢？」，第二个问题能结合上下文正确检索并回答病假政策。
