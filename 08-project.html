08 企业级 Agent 实战

阶段三 · 实战 难度：高级 前置：04–07 全部

学习目标

  • 把一个真实业务需求拆解为可递进的 Agent 阶段
  • 从单工具逐步演进到多工具、记忆、检索的企业级 Agent
  • 掌握每阶段的实现目标与增量功能

前置知识

  • 工具调用（06）、Agent（07）
  • 记忆（04）、RAG（05）

8.1 项目背景与需求

我们构建一个「智能客服 + 知识问答」企业级 Agent，服务一家电商公司。它需要能够：

  • 查询订单状态（需要调内部订单 API）
  • 查询物流信息（需要调物流 API）
  • 回答产品与售后政策问题（需要检索知识库）
  • 记住用户的上下文（如「我的订单」指哪一单）
  • 对退款等敏感操作做人工确认

我们不一次性写完，而是分四个阶段递进，每个阶段都可独立运行、可验证。这正是企业级开发的正确姿势——小步快跑，逐步增强。

💡 工程化约定 为保持可维护性，我们统一目录结构： 
agent_project/
├── tools.py          # 所有工具定义
├── agent.py          # Agent 组装
├── main.py           # 入口（命令行交互）
├── data/
│   └── policies.txt  # 知识库文档
└── requirements.txt  # 依赖

8.2 阶段一：单工具 Agent（最小可用）

实现目标：跑通「模型 → 工具 → 模型」的最短闭环，验证技术栈可用。

增量功能：一个 query_order 工具，根据订单号查询订单状态。

# tools.py
from langchain_core.tools import tool

# 模拟订单数据库
ORDERS = {
    "1001": {"status": "已发货", "amount": 199.0, "items": "无线耳机"},
    "1002": {"status": "待付款", "amount": 59.9, "items": "手机壳"},
}

@tool
def query_order(order_id: str) -> str:
    """根据订单号查询订单状态。order_id 为订单编号，如 1001。"""
    order = ORDERS.get(order_id)
    if not order:
        return f"未找到订单 {order_id}，请核实订单号。"
    return f"订单 {order_id}：{order['items']}，金额 {order['amount']} 元，状态：{order['status']}。"
# agent.py
from langchain_openai import ChatOpenAI
from langchain.agents import create_agent
from tools import query_order

model = ChatOpenAI(model="gpt-4o-mini", temperature=0)

agent = create_agent(
    model=model,
    tools=[query_order],
    system_prompt="你是电商客服助手，帮助用户查询订单。",
)

def chat(user_input: str) -> str:
    result = agent.invoke({"messages": [("user", user_input)]})
    return result["messages"][-1].content

if __name__ == "__main__":
    print(chat("帮我查一下订单 1001 的状态"))
订单 1001：无线耳机，金额 199.0 元，状态：已发货。
✅ 阶段一验收标准
  • 能正确调用 query_order 并返回结果。
  • 对不存在的订单号，返回友好提示而非崩溃。

8.3 阶段二：多工具 Agent（能力扩展）

实现目标：支持多类查询，模型能在多个工具间自主选择。

增量功能：新增 query_logistics 工具，与订单工具并存。

# tools.py 新增
LOGISTICS = {
    "1001": {"company": "顺丰", "no": "SF123456", "status": "运输中，预计明日送达"},
    "1002": {"company": "中通", "no": "ZT654321", "status": "待揽收"},
}

@tool
def query_logistics(order_id: str) -> str:
    """根据订单号查询物流信息。order_id 为订单编号。"""
    info = LOGISTICS.get(order_id)
    if not info:
        return f"未找到订单 {order_id} 的物流信息。"
    return f"订单 {order_id}：{info['company']} {info['no']}，状态：{info['status']}。"
# agent.py 修改
from tools import query_order, query_logistics

agent = create_agent(
    model=model,
    tools=[query_order, query_logistics],
    system_prompt="你是电商客服助手，可查询订单状态与物流信息。",
)

# 多工具协作：用户同时问订单和物流
print(chat("订单 1001 的状态和物流分别是什么？"))
订单 1001 的状态是"已发货"，
物流信息：顺丰 SF123456，运输中，预计明日送达。
⚠️ 常见误区：工具描述冲突 当多个工具功能相近时（如 query_order 和 query_logistics 都以 order_id 为参数），模型可能选错。务必在 docstring 里写清区别：一个查「订单状态」，一个查「物流」，让模型能区分。

8.4 阶段三：带记忆的 Agent（多轮上下文）

实现目标：支持多轮对话，记住「我的订单」「刚才说的」等指代。

增量功能：用 RunnableWithMessageHistory 注入历史，并用 trim_messages 控制长度。

# agent.py 修改
from langchain_core.chat_history import InMemoryChatMessageHistory
from langchain_core.runnables.history import RunnableWithMessageHistory
from langchain_core.messages import trim_messages

# 会话存储
store = {}

def get_history(session_id: str):
    if session_id not in store:
        store[session_id] = InMemoryChatMessageHistory()
    return store[session_id]

with_memory = RunnableWithMessageHistory(
    agent,
    get_history,
    input_messages_key="messages",
    history_messages_key="messages",
)

def chat(session_id: str, user_input: str) -> str:
    result = with_memory.invoke(
        {"messages": [("user", user_input)]},
        config={"configurable": {"session_id": session_id}},
    )
    return result["messages"][-1].content

# 多轮对话
print(chat("u1", "我的订单号是 1001"))
print(chat("u1", "帮我查一下我的订单物流"))   # 模型需要记住"我的订单"=1001
好的，已记住您的订单号是 1001。
您的订单 1001 物流：顺丰 SF123456，运输中，预计明日送达。
💡 记忆 + Agent 的注意点 Agent 的输入键是 messages（消息列表），因此 input_messages_key 和 history_messages_key 都设为 "messages"。这与第 04 章普通链（键名是 input/history）不同，务必对应。

8.5 阶段四：记忆 + 检索的企业级 Agent

实现目标：完整的企业级能力——多工具 + 多轮记忆 + RAG 知识检索 + 安全确认。

增量功能：① 接入知识库检索工具回答政策问题；② 退款工具加人工确认。

# tools.py 新增：RAG 检索工具 + 敏感操作工具
from langchain_openai import OpenAIEmbeddings
from langchain_chroma import Chroma
from langchain_text_splitters import RecursiveCharacterTextSplitter
from langchain_community.document_loaders import TextLoader

# 构建知识库（售后政策等）
loader = TextLoader("./data/policies.txt", encoding="utf-8")
chunks = RecursiveCharacterTextSplitter(
    chunk_size=500, chunk_overlap=50
).split_documents(loader.load())
vectorstore = Chroma.from_documents(
    chunks, OpenAIEmbeddings(model="text-embedding-3-small")
)
retriever = vectorstore.as_retriever(search_kwargs={"k": 3})

@tool
def search_policy(question: str) -> str:
    """在售后政策知识库中检索相关内容。question 为用户的政策疑问。"""
    docs = retriever.invoke(question)
    if not docs:
        return "知识库中未找到相关政策。"
    return "\n".join(d.page_content for d in docs)

# 敏感操作：退款（需人工确认，这里只发起申请）
@tool
def request_refund(order_id: str) -> str:
    """为用户提交退款申请。order_id 为订单编号。注意：这是敏感操作。"""
    return f"退款申请已提交（订单 {order_id}），等待人工审核确认。"
# agent.py 修改：组合所有工具
from tools import query_order, query_logistics, search_policy, request_refund

agent = create_agent(
    model=model,
    tools=[query_order, query_logistics, search_policy, request_refund],
    system_prompt=(
        "你是电商智能客服助手。你可以："
        "1. 查询订单状态与物流；2. 检索售后政策回答问题；"
        "3. 提交退款申请。"
        "涉及退款等敏感操作时，务必先向用户确认订单号与退款原因。"
    ),
)
❌ 安全红线：敏感操作必须人审 真实的退款、删除等操作，绝不能让模型直接执行。应实现为「申请 → 人工审核 → 确认执行」的两段式，或用 LangGraph 的 interrupt 机制在关键节点暂停等待人工批准（见第 09 章）。

8.6 交互入口（main.py）

把 Agent 包装成命令行交互程序，方便测试与演示：

# main.py —— 命令行交互入口
import sys
from agent import chat   # 导入第 08 章组装的 chat 函数

def repl():
    session_id = input("请输入会话 ID（如 u1，用于记忆隔离）: ").strip() or "u1"
    print("电商智能客服已启动，输入 'quit' 退出。\n")
    while True:
        try:
            text = input("你 > ")
        except (EOFError, KeyboardInterrupt):
            break
        if text.strip().lower() in ("quit", "exit", "退出"):
            break
        reply = chat(session_id, text)
        print(f"客服 > {reply}\n")

if __name__ == "__main__":
    repl()
💡 工程化：环境与配置分离 真实项目中，模型名、API 端点、知识库路径等应通过配置文件或环境变量注入，而非硬编码。这样测试环境与生产环境可以无缝切换。

8.7 测试你的 Agent

企业级 Agent 需要自动化测试。核心思路：固定输入，断言输出。可以用 pytest 编写测试：

# test_agent.py —— 用 pytest 测试关键行为
import pytest
from tools import query_order, query_logistics

def test_query_order_found():
    assert "已发货" in query_order.invoke({"order_id": "1001"})

def test_query_order_missing():
    assert "未找到" in query_order.invoke({"order_id": "9999"})

def test_query_logistics():
    assert "顺丰" in query_logistics.invoke({"order_id": "1001"})

# 运行：pytest test_agent.py -v
test_query_order_found ..... PASSED
test_query_order_missing ... PASSED
test_query_logistics ....... PASSED
✅ 最佳实践：分层测试
  • 工具层：单独测试每个工具的输入输出（mock 掉外部 API）。
  • Agent 层：用固定测试问题验证「是否调用了正确的工具」。
  • 端到端：少量核心场景走完整对话，作为回归测试。

8.9 动手练习

练习 8.1：跑通四阶段 （高级）

按上面四个阶段，一步步实现完整的电商客服 Agent，每个阶段都运行验证后再进入下一阶段。

验证方法：最终 Agent 能完成「查订单 + 查物流 + 查政策 + 记住上下文 + 退款申请」的完整对话流程。
练习 8.2：换一个业务场景 （高级）

把「电商客服」替换为你熟悉的场景（如 IT 运维助手、HR 问答、财务助手），套用同样的四阶段递进方法设计工具与知识库。

验证方法：画出你的工具清单、知识库内容、敏感操作与人工确认点，并实现阶段一。
练习 8.3：为 Agent 写测试 （高级）

用 pytest 为你的工具层写 3 个以上测试用例，覆盖「正常返回」「边界/异常输入」两种情况。

验证方法：运行 pytest -v，所有测试通过，且异常输入（如不存在的订单号）有友好处理而非崩溃。
